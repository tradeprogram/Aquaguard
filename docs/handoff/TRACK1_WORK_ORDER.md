## P0-1. 확률 스케일 보정 — 지금 파이프라인이 이것 하나로 막혀 있다

### 증상

`landslide_prob`이 **산청 어디서도 0.7에 도달하지 못합니다.** 그래서:

- `hours_to_critical`이 항상 `null`입니다 (`envelope.py`의 `CRITICAL_PROB = 0.7` 미달)
- Module O가 트리거되지 않아 **D·E·G·H가 한 번도 호출되지 않습니다**
- 노출자산·대피경로·피해비용이 전부 비어 있습니다

### 근거 (트랙③ 실측, 재현 가능)

현실적 입력으로 토성 8종 × 토심 4종 × 배수 6종을 전수 스윕한 결과입니다.

| 조건 | 최대 `landslide_prob` |
|---|---|
| 생비량면 실측(토심 0.44m, dNBR 0) | **0.017** |
| 생비량면 + 가공 dNBR 0.62/high | 0.55 |
| 시천면 최상위 격자(경사 29.8°, 토심 0.71m, dNBR 0.383) | **0.611** |
| 토심 `>100` 가정 + dNBR 0.62/high | 0.898 |

0.7을 넘기려면 토심 1m 초과를 가정해야 하는데, `ml_feature_table.csv`의 읍면
평균토심은 최대 0.598m(단성면)입니다. **즉 현실적 입력으로는 도달 불가능한
임계입니다.**

원인은 `fos.py`의 시그모이드입니다.

```
P = 1 / (1 + exp(k·(FoS − 1))),  k = 6.0
P ≥ 0.7  ⟺  FoS ≤ 1 − ln(3/7)/6 = 0.859
```

`fos_to_probability` docstring에 **"k는 산청 백테스트로 보정 예정 … 미보정"**,
`RUN_LOG`에 **"Rsat=200mm·Wmax=0.85·sigmoid k=6.0은 여전히 미보정"**이라고
적어두신 바로 그 항목입니다. 보정 전이라 확률이 운영 임계와 다른 축척에 있습니다.

### 지시

**이번 주 안에 확률 축척을 운영 가능한 범위로 맞추십시오.** 방법은 트랙①이 정하되,
결과물은 아래 둘 중 하나여야 합니다.

- **(A)** `k`(그리고 필요하면 `Rsat`·`Wmax`)를 백테스트로 보정해 산청 2025 실제
  발생 지점에서 `landslide_prob ≥ 0.7`이 나오게 한다
- **(B)** 보정이 발생부 좌표 없이는 불가능하다고 판단되면, **`CRITICAL_PROB`과
  Module O 임계를 현재 축척에 맞는 값으로 재유도**하고 그 유도 근거를 문서에 남긴다

> **(B)를 택할 경우 반드시 근거를 함께 내십시오.** "0.7이 안 나오니 0.5로 낮춘다"는
> 안 됩니다. 백테스트가 쓴 절대문턱(0.01~0.5%)처럼 **어떤 기준에서 나온 값인지**가
> 있어야 합니다. 임계를 근거 없이 내리면 백테스트 README에 직접 적으신
> "자주 하는 오독"에 저희가 걸립니다.

임계를 바꾸면 `module_o_orchestrator/orchestrator.py`의 `LANDSLIDE_THRESHOLD`도
같이 바뀌어야 합니다 — **그건 트랙③ 파일이니 값만 알려주시면 저희가 반영합니다.**

### 재현

```bash
python -c "
import json, copy
from module_a_landslide import parameters as P, run
ex = json.load(open('contracts/module_a.example.json', encoding='utf-8'))
best = (0, None)
for st in P.ST_CODE_TO_KR.values():
    for ad in P.AD_CODE_TO_KR.values():
        for dc in P.DC_CODE_TO_KR.values():
            inp = copy.deepcopy(ex['input'])
            inp['_soil'] = {'texture_kr': st, 'ad_kr': ad, 'dc_kr': dc}
            p = run(inp)['data']['landslide_prob']
            if p > best[0]: best = (p, (st, ad, dc))
print(best)
"
```

**완료 기준**: 데모 입력으로 `AQUAGUARD_MOCK_MODE=0` 파이프라인을 돌렸을 때
`alert_package.exposure.exposed_buildings`가 비어 있지 않을 것.

## P1-1. 데모 입력의 dNBR이 허위다 — 컨트롤타워 결정 사항

`ml_feature_table.csv` 기준 **생비량면은 평균 dNBR 0.0, 흉터비율 0.0**입니다.
산불 피해지가 아닙니다. 그런데 데모 입력에는 이렇게 들어가 있습니다.

```json
"dnbr": 0.62, "dnbr_class": "high", "days_since_fire": 121
```

목업 시절 가공값이며, **불타지 않은 곳을 불탄 것처럼 넣고 있는 상태**입니다.
그대로 두면 트랙①이 백테스트 README에 적으신 "성능 조작"에 해당합니다.

### 결정 — 데모 AOI를 시천면으로 옮긴다

| 읍면 | 흉터비율 | 평균경사 | 평균토심 | eval lift | 양성 |
|---|---|---|---|---|---|
| **시천면** | **19.2%** | 30.4° | 0.529m | **1.33** | 7 |
| 삼장면 | 16.5% | 31.2° | 0.482m | 1.21 | 4 |
| 생비량면 | 0.0% | 27.4° | 0.415m | — | 1 |

시천면은 흉터·경사·토심·lift가 모두 가장 유리하고, **산불–산사태 연쇄가 실제로
성립하는 유일한 후보**입니다. 생비량면을 유지하면 산불 축이 데모에서 사라집니다.

**트랙①이 할 일**: 시천면 안에서 데모 트리거 지점으로 쓸 **실좌표 1개와 그 지점의
`static` 전체**(slope_deg, dnbr, dnbr_class, days_since_fire, curvature, twi,
aspect_deg)를 확정해 주십시오. `물리_임계비율`이 가장 높았던 격자(경사 29.8°,
토심 0.71m, dNBR 0.383)가 1순위 후보입니다.

**트랙③이 할 일**: 그 좌표를 받는 즉시 노출자산 클립본과 3D 타일을 재생성합니다
(`build_aoi_exposure_layers.py`, `fetch_aoi_satellite.py`). 좌표만 주시면 됩니다.

## P2. 토사 퇴적 깊이(runout) — 계획만 회신

지도의 토사 3D 볼륨은 아직 **손으로 그린 경로 + 슬라이더**입니다. Module A가 도달
거리나 퇴적 깊이를 내지 않아 근거가 없어서 저희가 채우지 않았습니다.

침수 쪽은 이번에 실제 모형값으로 연결했습니다 — SFINCS 최대침수심을 0.3/1/2/5m
구간으로 폴리곤화해 **547개 폴리곤, 최심 p90 10.83m**가 3D로 올라갑니다. 토사도
같은 자리가 비어 있는 상태입니다.

**지시**: USGS PWFDF-R 계열 runout을 붙일 계획이 있는지, 있으면 일정만 회신하십시오.
12월 전에 어렵다면 제안서에 "향후 과제"로 두겠습니다 — **없는 걸 있다고 하지 않는
것이 이 프로젝트 원칙**이므로 없으면 없다고만 알려 주시면 됩니다.

## 참고 — 트랙③이 이미 처리한 것 (중복 작업 방지)

A/B가 실물이 되면서 드러난 문제들입니다. 트랙① 코드와는 무관합니다.

- `TriggerRequest`가 `module_a_extra` 등을 Pydantic 단계에서 버려 **HTTP 경로에서만
  위험도가 0**이었습니다 — 필드 선언 추가
- Module O가 A/B에 좌표만 넘기고 관측값을 안 넘겼습니다 — 목업이 입력을 무시해서
  안 보이던 문제
- What-if 슬라이더가 `module_a_extra`를 통째로 덮어써 경사·dNBR이 사라졌습니다
- 임계 미달이면 경보를 저장하지 않아 지도가 아무것도 못 받았습니다 — `감시중` 상태 추가
- Module B 침수심 래스터를 3D 지도에 연결 (`fim.py` 깊이 밴드, `flood-model-3d` 레이어)
- 제안서를 백테스트 결과로 재작성 — 음성 결과(ROC-AUC 0.469, 농축 0.82배, ML 기각
  p=0.074)를 양성과 같은 비중으로 실었고, "자주 하는 오독" 표를 그대로 반영했습니다
