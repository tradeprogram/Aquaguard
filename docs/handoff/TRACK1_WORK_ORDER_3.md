## 먼저 — 2차 지시서(경사 격자)는 **긴급도를 내립니다**

`TRACK1_WORK_ORDER_2.md`에서 경사 격자를 P0로 요청드렸는데, **더 이상 데모를
막지 않습니다.** 대신 트랙③이 Module O의 트리거 임계를 0.7 → 0.5로 내렸고, 그
근거는 아래와 같습니다.

```
P = 1/(1 + exp(k·(FoS − 1)))          k = 6.0, 미보정

FoS = 1.0    ⟺  P = 0.5      k와 무관하게 항상 성립
FoS = 0.859  ⟺  P = 0.7      k = 6 일 때만. k를 보정하면 이 대응이 바뀐다
```

`FoS = 1`은 버티는 힘과 무너뜨리는 힘이 같아지는 물리적 파괴 한계이고,
**시그모이드에서 유일하게 미보정 파라미터 `k`에 불변인 점**입니다. 0.7은 `k = 6`
이라는 임의값에 딸려 있을 뿐이었습니다. 설계 실무가 FoS 1.3~1.5를 요구하는 걸
생각하면 FoS = 1 발동은 이르기는커녕 늦습니다.

과다 발동도 아닙니다 — 트랙①이 사전계산한 레이어 기준으로 `P ≥ 0.5`는 산청 AOI
452km² 중 **0.238km²(0.053%)** 뿐이고, 트랙① 자신도 이 값을 `warning` 레이어
기준으로 쓰고 계십니다.

**k를 보정하시면 이 임계도 다시 유도해야 합니다.** 그때는 0.7이 맞을 수도 있습니다.
값이 정해지면 `module_o_orchestrator/orchestrator.py`의 `LANDSLIDE_THRESHOLD`는
트랙③이 반영합니다.

경사 격자는 여전히 필요하지만 이유가 바뀌었습니다 — **데모를 살리기 위해서가
아니라 정합성 때문**입니다. `run()`은 계약값 `static.slope_deg`(32.5°)를 쓰고
`scripts/45`의 레이어는 실제 5m 경사 래스터를 쓰므로, 같은 지점에서 점 평가와
폴리곤 판정이 어긋납니다. **P1로 낮춥니다.**

## P0. `CRITICAL_PROB`을 어떻게 둘지 결정해 주십시오

### 현재 상태

```
Module O  LANDSLIDE_THRESHOLD = 0.5   "대응을 시작한다"
Module A  CRITICAL_PROB       = 0.7   "hours_to_critical 을 세는 기준"
```

두 값이 달라진 건 트랙③이 O만 내렸기 때문입니다. **A는 손대지 않았습니다** —
`CRITICAL_PROB`은 트랙① 소유이고, 두 임계가 같은 것을 가리켜야 하는지가
설계 판단이라 임의로 맞추지 않았습니다.

### 저희 의견 (참고만 하십시오)

**둘은 다른 개념이라 굳이 같을 필요가 없어 보입니다.**

- O의 임계 = "지금부터 대응 절차를 돌린다"
- A의 `CRITICAL_PROB` = "얼마나 더 있으면 더 나빠지는가"의 기준선

경보 체계에서 행동 임계가 위험 임계보다 낮은 건 정상입니다. 오히려 `CRITICAL_PROB`
을 0.5로 맞추면 **현재 데모에서 `hours_to_critical`이 `0.0`이 됩니다**(이미 초과).
그러면 `time_budget_hours`가 0이 되어 대피 시간 여유가 사라지므로, 그게 의도인지
확인이 필요합니다.

**결정해서 알려만 주시면 됩니다.** 바꾸든 두든 그 근거를 `envelope.py` 주석에
남겨 주십시오 — 지금은 두 숫자가 왜 다른지가 코드 어디에도 없습니다.

## P0. `hours_to_critical`이 계속 `null`입니다 — 예보 시계열이 없습니다

### 증상

```
landslide hours_to_critical : null
flood     hours_to_critical : 3.7
```

Module O는 둘 중 작은 값으로 대피 가용시간을 잡으므로 **지금은 하천범람 값만으로
돌아갑니다.** 산사태가 골든타임 서사의 주인공인데 정작 시간을 못 내고 있습니다.

### 원인 (임계 문제가 아닙니다)

`forecast.extract_series()`가 예보 시계열을 못 찾습니다. 데모 입력의
`dynamic.source`는 `"observed"`이고 `rainfall_1h_mm`은 **과거** 강우라, 코드가
정의한 두 경로 어느 쪽에도 안 걸립니다.

```python
1) input["_forecast"]["rain_1h_mm"]                    # 명시 주입 — 없음
2) dynamic.source == "forecast" 이면 dynamic.rainfall_1h_mm   # source가 observed
→ 빈 리스트 (미래 없음) → hours_to_critical = null
```

### 지시

**산청 2025-07-19 시나리오의 LDAPS 예보 시간강우 시계열을 주십시오.**
`scripts/09_kma_rainfall_client.py`가 이미 기상청 API허브를 쓰고 있으니 그 경로를
재사용하시면 됩니다.

형식은 이미 코드가 정한 대로입니다.

```json
"_forecast": {
  "rain_1h_mm": [24.0, 31.5, 28.0, 19.0, ...],
  "source": "LDAPS 2025-07-19T08:00 발표"
}
```

- 기준시각 08:00부터 시간 단위로, 최소 12시간 이상
- **leakage 금지** — 08:00 시점에 실제로 발표돼 있던 예보만. 사후 실측을 예보인
  것처럼 넣으면 백테스트 전체가 무의미해집니다(트랙①이 세운 원칙 그대로)

**트랙③이 할 일**: 받는 즉시 `contracts/module_o.example.json`의 `module_a_extra`에
넣고 Module O가 그대로 전달하게 합니다. 이미 통로가 있어 배선은 필요 없습니다.

**완료 기준**: `landslide.hours_to_critical`이 숫자로 나올 것.
